## Обзор

```
 ┌───────────────────────── процесс приложения ───────────────────────────┐
 │                                                                         │
 │  MainActivity ── Compose UI (ui/FeatherW8App и экраны)                  │
 │       │  MediaController (Media3)                                       │
 │       ▼                                                                 │
 │  PlaybackService ── MediaSession ── ExoPlayer                           │
 │       │                                  │                              │
 │       │ счётчик (ActualPlayCounter)      │ DsdExtractor ─ JNI ─ libdsdpcm
 │       ▼                                  ▼                              │
 │  PlayCountStore (SharedPreferences)   аудиовыход                        │
 │                                                                         │
 │  MediaLibraryRepository ── MediaStore ──► List<MusicTrack>              │
 │       └── DsdLibrary (теги, обложки, длительности файлов DSD, кэш)      │
 └─────────────────────────────────────────────────────────────────────────┘
```

Всё живёт в одном процессе. Интерфейс не обращается к плееру напрямую: он говорит с ним через Media3
`MediaController`, а сам плеер живёт в `MediaSessionService`, поэтому воспроизведение переживает закрытие активити,
а уведомление, экран блокировки и кнопки наушников управляют тем же плеером.

Kotlin, Jetpack Compose (Material 3), AndroidX Media3 (ExoPlayer, Session, Extractor), kotlinx.coroutines и небольшая
библиотека на C++ (CMake / NDK) для преобразования DSD в PCM.

| `data/MediaLibraryRepository.kt` | Сканирует MediaStore в `MusicTrack` |

| `data/ActualPlayCounter.kt` | Логика «реально прослушано 90 %» |
| `data/PlayCountStore.kt`, `TrackInfoStore.kt` | Сохранённые счётчики прослушиваний и измеренные битрейты |
| `data/CoverDiskCache.kt` | Дисковый кэш JPEG-миниатюр |
| `ui/FeatherW8App.kt` | Корневой composable: всё состояние приложения, навигация, связка всего ниже |
| `ui/theme/` | Цвета, варианты акцента, профиль устройства (Nothing / realme / прочие), `FeatherW8Theme` |

| `ui/screens/` | Library, Playlists, Albums/Artists/детали, Queue, Settings |

## Процессы и потоки

Один процесс; значимые потоки:

| Работа | Где |
|---|---|
| UI, Compose, колбэки `MediaController`, колбэки `PlaybackService` и опрос счётчика | главный поток |
| Скан библиотеки (запросы MediaStore, чтение заголовков и тегов DSD) | `Dispatchers.IO` |
| Фильтрация, сортировка, группировка альбомов и исполнителей, умные плейлисты | `Dispatchers.Default` |
| Декодирование обложек (не больше 3 одновременно), прогрев обложек (по одной) | `Dispatchers.IO` |
| Декодирование звука, в том числе извлечение и преобразование DSD | собственные потоки загрузки и воспроизведения ExoPlayer |
| Чтение счётчиков и сборка медиаэлементов для новой очереди | `Dispatchers.IO` / `Default` |

## Интерфейс и состояние

Активити одна, `MainActivity`, библиотеки навигации нет. `ui/FeatherW8App.kt` — корневой composable; он владеет
практически всем состоянием в локальных переменных `remember` / `rememberSaveable` и передаёт вниз обычные значения и
колбэки в экраны без состояния.

**Страницы.** `AppPage` (в `ui/model/UiModels.kt`) перечисляет пункты назначения: `LIBRARY`, `PLAYLISTS`, `SETTINGS`,
`ALBUMS`, `ARTISTS`, `ALBUM_DETAIL`, `ARTIST_DETAIL`, `PLAYLIST_DETAIL` (и устаревший `QUEUE`, который при старте
заменяется на `LIBRARY`). Текущая страница хранится в `rememberSaveable`. Полный плеер — не страница, а слой
(`PlayerOverlays`), который показывается, пока `playerOpen` истинно; внутри него двухстраничный пейджер держит
плеер (страница 0) и очередь (страница 1).

**Вкладки Library и Playlists** — две страницы `HorizontalPager`. Выбранная вкладка и пейджер должны сходиться, кого
бы пользователь ни тронул, и это непросто:

- нажатие на вкладку задаёт `page`; эффект затем анимирует пейджер к ней, сравнивая с **целевой** страницей пейджера
  (а не с последней успокоившейся), так что быстрое нажатие назад во время движения разворачивает анимацию;
- свайп успокаивает пейджер, а тот возвращает значение в `page`;
- соседняя вкладка остаётся собранной (`beyondViewportPageCount = 1`), чтобы переключение никогда не строило страницу
  посреди анимации.

**Производное состояние** считается вне главного потока и публикуется обратно: видимый список треков (фильтры,
поиск, сортировка), альбомы и исполнители, умные плейлисты, счётчики. Если повторный скан даёт список, равный
текущему, он не присваивается, так что возвращение в приложение не запускает всё это заново.

**Общее состояние и плеер.** Очередь, которую показывает UI, — это `List<MusicTrack>` внутри `FeatherW8App`,
зеркалирующий плейлист плеера (см. [Известные ограничения](#известные-ограничения)).

**Оформление.** Тема чисто чёрная с выбираемым акцентом (`LocalFeatherAccent`). На телефоне Nothing по умолчанию
используется системный шрифт `NDot55`; `DeviceProfile` определяется по строкам `Build`.

## Воспроизведение

`PlaybackService` создаёт `ExoPlayer` и `MediaSession`:

- **Экстракторы.** Стандартные плюс `DsdExtractor` первым в списке, так что файлы DSD забирает он (он определяет
  сигнатуру `DSD ` / `FRM8`).
- **Звук.** `AudioAttributes.DEFAULT` с обработкой аудиофокуса; `setHandleAudioBecomingNoisy(true)` ставит на паузу,
  когда выдёргивают наушники.
- **Wake lock.** `setWakeMode(C.WAKE_MODE_LOCAL)` держит частичный wake lock во время игры, чтобы процессор не засыпал
  между аудиобуферами при выключенном экране.
- **Повтор и перемешивание** сохраняются в SharedPreferences при каждом изменении и восстанавливаются при создании
  сервиса. Одна кнопка плеера переключает по кругу Repeat off → all → track → Shuffle (перемешивание показано как
  четвёртый «режим»; хранится как повтор выключен + перемешивание включено).
- **Активити сессии.** `setSessionActivity` указывает на `MainActivity` с действием `ACTION_OPEN_PLAYER`, так что
  нажатие на карточку уведомления открывает приложение и полный плеер (см. [Намерения извне](#намерения-извне)).

**Запуск воспроизведения.** `playTracks(items, index)` в `FeatherW8App` задаёт очередь UI, сразу показывает плеер с
выбранным треком и строит `MediaItem` на `Dispatchers.Default`, прежде чем передать их контроллеру (`setMediaItems`,
`prepare`, `play`), чтобы анимация выезда не подвисала. `MediaItem` несёт идентификатор трека как `mediaId`, его URI,
название/исполнителя/альбом, URI обложки (выбранная пользователем обложка важнее обложки медиаиндекса) и
длительность, найденную библиотекой.

**Правка очереди.** `moveQueueTrack` и `removeQueueTrack` применяют изменение и к контроллеру (`moveMediaItem`,
`removeMediaItem`), и к списку UI вместе. Удаление последнего трека закрывает плеер, а это ещё и останавливает его и
очищает.

**Мини-плеер.** `MiniPlayerBar` опрашивает позицию контроллера каждые 250 мс, пока виден и играет (состояние локально
для панели, так что остальной экран не перерисовывается); вертикальное перетаскивание следует за пальцем и
закрывает карточку за порогом.

## Подсчёт прослушиваний

Трек засчитывается, когда **действительно прослушано** больше 90 %. Логика в `data/ActualPlayCounter.kt`, ею управляет
`PlaybackService`; значение сохраняет `PlayCountStore`.

Счётчик работает **отрезками**: от момента, когда плеер стартует, возобновляется или приземляется после перемотки, до
момента, когда он ставится на паузу, перематывается или трек заканчивается. Ценность отрезка — позиция плеера в
момент закрытия минус та, с которой он начался, поэтому от частоты опросов она не зависит. (Прежняя версия
складывала мелкие шаги между опросами и отбрасывала любой шаг больше 1,5 с; на телефоне, который притормаживает
приложения при выключенном экране, это выбрасывало почти всё время.)

Две защиты:

- **перемотка** закрывает отрезок до прыжка и открывает новый после него, так что пропущенное время никогда не
  засчитывается, а сыгранное до перемотки — засчитывается;
- отрезок не может стоить больше, чем прошло по **часам** с его начала (плюс допуск 750 мс), так что скачок
  позиции, о котором не сообщили, тоже не засчитывается.

Сервис закрывает отрезки по собственным событиям плеера, а не по следующему опросу: `onIsPlayingChanged`
(пауза/возобновление), `onPositionDiscontinuity` с перемоткой, смена трека или автопереход (он завершает старый трек
на его конечной позиции и запускает новый счётчик). Опрос раз в 250 мс всё равно идёт, поэтому прослушивание
фиксируется в момент прохождения 90 %, а не в конце трека.

Длительность для правила 90 % берётся из плеера, а если плеер её не знает (VBR-MP3 без заголовка длины) — из
длительности библиотеки, переданной в `MediaItem`. Трек без известной длительности не засчитывается никогда.

## Библиотека

`MediaLibraryRepository.scanInternalStorage()` строит список `MusicTrack`:

1. Запрашивает `MediaStore.Audio` только на **основном внешнем томе**, самые новые первыми.
2. Запрашивает `MediaStore.Files` по именам, заканчивающимся на `.dsf`, `.dff` или `.dsd`, потому что медиаиндекс часто
   не относит файлы DSD к аудио; строки, уже найденные на шаге 1, пропускаются.
3. Для каждого трека DSD заменяет то, что MediaStore угадал (он называет альбомом имя папки, исполнителя и длительность
   не знает), тем, что говорит сам файл: см. [Конвейер DSD](#конвейер-dsd).
4. Сортирует по дате добавления и **заранее считает** подписи, которые UI показывает снова и снова (расширение,
   подпись формата, подзаголовок, подпись размера, URI обложки), в потоке скана, а не в composable.

Скан идёт при входе в приложение (`onStart`) и по запросу из настроек. Идентификаторы всех увиденных треков
сохраняются, чтобы следующий скан мог сказать, сколько из них новые.

**Идентичность.** Идентификатор трека — `_ID` из MediaStore в виде строки. Избранное, плейлисты, счётчики,
кэшированные битрейты и пользовательские обложки привязаны к нему.

**Группировка** (`ui/model/Collections.kt`): альбомы по `albumId|исполнитель|альбом` (или `исполнитель|альбом`, когда
идентификатор альбома неизвестен, как у DSD), исполнители по имени; всё сортируется без учёта регистра.

**Умные плейлисты:** *Recently added* = 10 самых новых; *Hi-Res* = DSD или скорость потока не меньше 200 000 байт в
секунду, оцененная по размеру и длительности; *Most played* = до 10 с хотя бы одним полным прослушиванием;
*Favorites*.

**Фильтры.** Минимальные размер и длительность применяются только к списку Library. Трек с длительностью 0
(неизвестной) фильтр длительности проходит.

## Конвейер DSD

```
файл DSF / DSDIFF
   └─ DsdExtractor            определить, разобрать контейнер, отдать перематываемый поток
       └─ DsdDataReader       разложить и развернуть биты блоков DSF; DSDIFF уже чередуется
           └─ NativeDsdDecoder → dsd_jni.cpp → libdsdpcm
               на входе кадры DSD по 1/75 с, на выходе 16-битный PCM 88,2 кГц
```

**Разбор контейнера** (`DsdFileInfo`). DSF: чанк `DSD `, `fmt ` (каналы, частота, число сэмплов, размер блока), затем
`data`. DSDIFF: форма `FRM8`, `PROP` (`FS`, `CHNL`, `CMPR`), затем чанк `DSD `; файлы со сжатием DST отклоняются. Каналов
должно быть 1–6, а частота — кратна 600 Гц.

**Извлечение.** Каждый вызов `read` заполняет один входной кадр — 1/75 с чередующегося DSD (для стерео DSD64 это
9 408 байт), преобразует его и отдаёт полученную 1/75 с 16-битного PCM одним сэмплом (4 704 байта для стерео).
Последний неполный кадр дополняется паттерном тишины DSD `0x69`. В DSF каждый канал хранится отдельными блоками,
младшим битом вперёд, поэтому блоки чередуются, а каждый байт разворачивается по битам перед преобразованием.

**Перемотка.** `DsdSeekMap` переводит время в байтовую позицию в файле (с выравниванием по блокам для DSF). Так как
фильтры конвертера хранят состояние, перемотка закрывает декодер и открывает новый, затем ставит читателя на нужный
кадр.

**Нативный конвертер** (`dsd_jni.cpp`). Дескриптор держит конвертер `libdsdpcm`, настроенный через
`dsdpcm_init_multistage` (75 кадров/с, скорость DSD, выход 88 200 Гц, 64-битная плавающая точка). `nativeConvert`
обрабатывает один кадр и квантует double в 16 бит с ограничением. Библиотека собирается из целей CMake типа `OBJECT`
и `STATIC`, которые линкуются в один `libfeather_dsd.so` вместе с JNI-кодом; это описано в
[THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md). Движок под LGPL-2.1; его исходники встроены в репозиторий.

**Теги, обложка и длительность.** MediaStore не знает ни одного из них для DSD, поэтому `DsdMetadataReader` читает их из
файла через дескриптор с произвольным доступом: у DSF тег ID3v2 лежит по смещению, записанному в заголовке (байты
20–27), у DSDIFF есть чанк `ID3 ` (запасной вариант — чанки `DIIN` с названием и исполнителем). Данные ID3 декодирует
`Id3Decoder` из Media3 (название `TIT2`, исполнитель `TPE1`/`TPE2`, альбом `TALB`, картинка `APIC`, предпочитается
лицевая обложка). Точный битрейт — `частота × каналы`.

`DsdLibrary` кэширует результат по файлу в `cacheDir/dsd-meta/`, ключ — хеш от `"id:size"`: JSON-файл со значениями и,
если есть обложка, JPEG (уменьшенный до 1 024 px; как есть, если уже небольшой). Файл, который прочитать не
удалось, запоминается как таковой. `MusicTrack.withDsdInfo` применяет это: название, исполнитель, альбом, длительность,
`albumId = -1` (чтобы группировка шла по настоящим тегам, а не по папке), URI обложки, точный битрейт и строка
деталей «DSD128 · stereo».

## Обложки

- **Память:** `LruCache` на 24 МБ, ключ `uri@pixels`.
- **Декодирование:** не больше 3 одновременно (семафор), на `Dispatchers.IO`, отменяется, когда строка уезжает с
  экрана. Миниатюры 192 px, обложка на весь экран 720 px. На Android 10+ сначала пробуется
  `ContentResolver.loadThumbnail`; иначе изображение декодируется с уменьшением.
- **Диск:** миниатюры (запросы ≤ 512 px) хранятся как JPEG (качество 85) в `cacheDir/covers/`, имя — хеш ключа, пишутся
  во временный файл и переименовываются. Каталог обрезается до 96 МБ, сначала самые старые.
- **Прогреватель:** `CoverWarmer` создаёт недостающие миниатюры в фоне по одной, останавливаясь, пока список
  прокручивается.
- **Какая картинка:** обложка, выбранная пользователем (`CustomArtworkStore`, хранится как URI с сохранённым правом
  чтения), важнее всего; затем обложка из файла DSD (`MusicTrack.coverUri`); затем обложка альбома из медиаиндекса.

## Перестановка в списках

В Compose нет готового перетаскивания для ленивых списков, поэтому `ui/components/Reorderable.kt` реализует его
сам. Его используют очередь и плейлисты, созданные пользователем.

`ReorderState` следит за удерживаемой строкой (по ключу) и за тем, где палец поставил её верхний край в области
просмотра списка. Удерживаемая строка в списке не двигается, пока палец идёт: она рисуется у пальца со смещением
(`reorderLayer`), которое отсчитывается от того места, где её сейчас держит список, так что строка остаётся под
пальцем, когда список перестраивается под ней. Когда центр удерживаемой строки пересекает другую переставляемую
строку, вызывается `onMove(from, to)` и ожидается, что список перестроится. Запрошенный, но ещё не размещённый
перенос второй раз не запрашивается. Пока строка удерживается у верхнего или нижнего края, корутина каждый кадр
прокручивает список фиксированным шагом.

Жест (`reorderGesture`, долгое нажатие и перетаскивание) подключён **внутри** обработки нажатий строки, чтобы
первым видеть касание и поглощать его; поэтому «удержал и отпустил» не засчитывается ещё и как нажатие.

Позиции, передаваемые в `onMove`, считают только переставляемые строки (задаются смещение заголовка и число строк).
Очередь применяет их к плееру и своему списку; плейлисты применяют **по идентификатору трека** (`movedOver`), потому
что список на экране пропускает треки, чьих файлов уже нет, так что позиция на экране — не позиция в сохранённом
плейлисте.

## Намерения извне

`MainActivity` имеет режим `singleTask`, поэтому запущенное приложение получает новые намерения в `onNewIntent`, а не
вторую копию.

- **Открыть с помощью.** Два фильтра `VIEW` в манифесте: любой `audio/*` (и `application/ogg`) и URI `content`/`file`,
  путь которых заканчивается на `.dsf`, `.dff` или `.dsd` (файловый менеджер часто сообщает DSD как общий тип; в
  Android `pathPattern` нужен один шаблон на каждое число точек в пути, отсюда повторы). URI становится состоянием UI;
  когда сервис плеера подключён, `resolveExternalTrack` сопоставляет его с треком библиотеки (по URI или
  идентификатору MediaStore) или строит отдельный трек (id `ext:<uri>`, имя и размер от провайдера, теги DSD через
  `DsdLibrary`) и воспроизводит его.
- **Открыть плеер.** Активити сессии шлёт `ACTION_OPEN_PLAYER`. Запрос ждёт, пока станет известен играющий трек
  (после скана библиотеки при холодном старте), и затем открывает полный плеер; если ничего не играет, он
  отбрасывается.
- Оба игнорируются при пересоздании активити (`savedInstanceState != null`) или восстановлении из истории, так что поворот
  экрана их не повторяет.

## Хранимые данные

Всё закрыто для других приложений.

**SharedPreferences `featherw8`**

| Ключ | Содержимое |
|---|---|
| `favorites` | Множество идентификаторов треков |
| `user_playlists` | JSON-массив `{id, name, trackIds}` |
| `sort_mode` | `TITLE`, `ADDED` или `PLAYS` |
| `minimum_size_kb`, `minimum_duration_seconds` | Фильтры библиотеки (устаревший `minimum_size_mb` переносится) |
| `accent_color` | Идентификатор акцента (`red`, `violet`, `cyan`, `mint`, `amber`, `rose`) |
| `nothing_dot_font_enabled` | Переключатель NDot (телефоны Nothing) |
| `playback_repeat_mode`, `playback_shuffle_enabled` | Восстанавливаются сервисом |
| `known_track_ids` | Идентификаторы, увиденные последним сканом, чтобы считать новые треки |
| `custom_cover_uri_<id>` | Обложка, выбранная пользователем |

**SharedPreferences `featherw8_play_counts`:** `full_plays_<id>` → целое число.

**SharedPreferences `featherw8_track_info`:** `bitrate_<id>` → `[~]бит/с|размер` (`~` — оценка; размер заставляет заново
измерить замещённый файл).

**Каталог кэша:** `covers/` (миниатюры) и `dsd-meta/` (теги и обложки DSD). Система может их удалить; они
восстанавливаются.

## Тесты

JVM-юнит-тесты (`app/src/test`), запускаются `./gradlew :app:testDebugUnitTest` и в CI:

| Тест | Что покрывает |
|---|---|
| `DsdExtractorTest` | Разложение блоков DSF и порядок бит; разбор несжатого DSDIFF |
| `DsdMetadataReaderTest` | Параметры потока, ID3 название/исполнитель/альбом/обложка (ASCII и UTF-16) для DSF и DSDIFF, запасной `DIIN`, подпись скорости DSD |
| `ActualPlayCounterTest` | Правило 90 %, редкий опрос, скачки без сообщения, перемотки, поздняя пауза, один засчёт на трек |
| `ListEditsTest` | `moved` / `movedOver`, включая идентификаторы, не соседние в хранилище |

Инструментальных (на устройстве) тестов нет: интерфейс, сервис плеера и JNI-конвертер проверяются вручную на
телефоне.

Заметка для тех, кто пишет тесты с Media3: `ParsableByteArray` опрашивает фреймворк Android, чтобы понять, идёт ли
тест, и на обычной JVM не инициализируется. Тесты метаданных сначала вызывают
`ParsableByteArray.setShouldEnforceLimitOnLegacyMethods(false)`, что пропускает эту проверку.

## Известные ограничения

- **Очередь на экране не восстанавливается из плеера.** Очередь — список, который держит UI; у плеера свой. Если
  активити пересоздаётся, пока музыка играет (приложение убрали из недавних и открыли снова из уведомления, либо
  поворот экрана), экран очереди начинается пустым, хотя в плеере треки остались, пока ты снова не начнёшь играть из
  списка. Сам текущий трек при этом по-прежнему находится через библиотеку.
- **Нет ViewModel; один большой корневой composable.** `FeatherW8App.kt` (около 1 100 строк) держит состояние и
  логику. То, что является только отображением, вынесено (диалоги, слои плеера, экраны), а само состояние — нет,
  поэтому большая его часть локальна в `remember` и лишь часть переживает смерть процесса.
- **Идентификаторы берутся из MediaStore.** Файл, переиндексированный под новым идентификатором, выглядит новым треком.
- **Вывод DSD — PCM**, а не нативный DSD, и DSDIFF со сжатием DST не поддерживается.
- **Сканируется только основной внутренний том.**
- **Нет тестов на устройстве;** см. выше.
